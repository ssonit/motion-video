# Motion — video studio

Goal: the user sends a **video link or file**; Claude watches it, then builds a **similar video**
(usually English, no human presenter, our own visuals) with Remotion.

## When the user sends a video link or file
Use the `clone-video` skill (`.claude/skills/clone-video/SKILL.md`). Short version:
1. `python tools/analyze.py "<url-or-file>" <slug>` → `references/<slug>/` (video + contact sheets)
2. Read the sheets, write `references/<slug>/analysis.md` (structure, style, script).
3. Write the new script `studio/content/<new-slug>/slides.json`.
4. `python tools/tts.py <new-slug> --voice ...` then build `studio/src/videos/<Name>.tsx`, register it in `studio/src/Root.tsx`.
5. `python tools/render.py <CompId> <output-name>` → `output/<output-name>.mp4`.

## Conventions (learned from the user's feedback)
- 1280x720, 30 fps. Dark-orange "ember" look is the house style; other palettes per scene are welcome.
- **Every scene must look different** (illustration, app window, phone, chart, before/after, org chart…).
  One repeated card template was rejected twice as boring ("only one form of scene"). The reference videos cut
  every ~5–8 s between: full-bleed 3D-style illustrations (desk at night, team at desks, devices ring, beach, sunset
  fortress, water cooler…), app screen recordings, phone walkthroughs with callouts, neon panels, big chapter cards,
  data screens and dark text slides. Plan ~1 shot per sentence (40+ shots for 5 min), assign each shot a different
  look from that list, and look at every shot before delivering.
  **Catalogue of reusable shots/blocks, the Bot mascot spec (§7) and the sound/voice catalogue (§8): `studio/LIBRARY.md` — check it before drawing anything new.**
  Hand-drawn SVG/CSS scenes (we have no image generator): `src/lib/Env.tsx` (rooms, monitors, skylines, posters,
  sunsets, castle…), `src/videos/rich/Illustrations.tsx` + `Screens.tsx`; see `BotGuideRich.tsx` (41 shots).
  Offer to write image prompts if the user wants real AI art.
- **Each shot = a change the viewer can SEE.** Write one line per shot ("what the viewer goes through"); if the change is only
  announced by the title, redesign the shot. Never pad leftover time with slow zoom/floating/repeated titles — cut shorter or hold on purpose.
- **No human photos / presenter** unless the user supplies their own footage. References are hybrids (motion graphics + real
  talking-head PiP + real screen recordings): use the footage-slot templates (`studio/LIBRARY.md` §4b, `lib/Slot.tsx`,
  `content/<slug>/footage.json`) and say which shots need the user's clips. Otherwise use the orb mascot (`Mascot`).
- **Lively voice**: edge-tts neural voices, never the offline Windows voices (too flat). Default en-US-GuyNeural;
  female en-US-AriaNeural. Vietnamese: vi-VN-HoaiMyNeural / vi-VN-NamMinhNeural.
- **Sound design matters**: whoosh at each scene start, tick on every card/chip, typing sound on typed text,
  ding on key moments, quiet beat music bed. Always finish with loudnorm (render.py does it).
- Captions = the narration, split by sentence. Keep scene content above y≈545 so 2-line captions never overlap.
- Fonts: Inter + JetBrains Mono (English). For Vietnamese text use Be Vietnam Pro (JetBrains Mono has no Vietnamese).
- Don't copy a reference's branding/faces/product claims; mirror structure and pacing, write our own words.
  If the product's real features are unknown, keep names generic.

## Verify before delivering
- `cd studio && npm run typecheck`
- Preview: `python tools/render.py <CompId> <name> --scale 0.5`, pull frames with ffmpeg, read them as images.
- We cannot listen to audio: check levels with `ffmpeg -af volumedetect`, and say plainly that it was not heard.
- Deliver with SendUserFile; report length and what was/wasn't checked.

## Environment notes
- Windows 11; Node 24; Python 3.13 (`pip install edge-tts yt-dlp numpy` already done); ffmpeg at C:\ffmpeg\bin.
- edge-tts occasionally returns "NoAudioReceived": tts.py retries; if it persists, wait and retry later.
- Douyin/TikTok links often need login: if yt-dlp fails, ask the user to download the file and send the path.
  Tried on v.douyin.com/SZLcmK8JVVA (2026-11-18): yt-dlp → 403 "fresh cookies needed"; built-in browser → login wall
  on the video page, and the player streams via blob (no downloadable URL). Don't use the user's browser cookies
  (`--cookies-from-browser`) without asking. Fallback: the user saves the mp4 (SaveTik etc.) and sends the path,
  or we build from the pasted caption text only (say clearly that the visuals were not seen).
- Don't run `du` over studio/node_modules (very slow).
- **C: can run out of space** (it hit 0 GB once → "ENOSPC" during render). tools/render.py already puts temp files in
  `D:\Project\motion\.tmp`; for manual `npx remotion render` set TEMP/TMP to that folder first. Safe to delete `.tmp/*`
  and leftover `%LOCALAPPDATA%\Temp\remotion-*` folders. Write scratch images to `.tmp/`, not C:.
- **APPROVED (2026-11-19): `BotGuideReal` (output/bot-guide-real-en_female-aria.mp4) is the standard look for Grok Bot videos.**
  For any new Grok Bot video, copy `BotGuideReal.tsx` + reuse `src/videos/real/` (ui.tsx, ScenesA/B, BotMark) and LIBRARY.md §9b; never go back to the orb Mascot or generic windows.
- Grok Bot visuals: the real UI is only a loose reference (user said "không cần quá sát"); keep our own look, borrow layout/colours/mark from `references/grok-bot-ui/`.
